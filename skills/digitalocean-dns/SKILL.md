---
name: digitalocean-dns
description: Inspect existing DigitalOcean DNS zones and add authorized A, AAAA, CNAME and TXT records through the registered DigitalOcean DNS MCP connection.
---

Find **DigitalOcean DNS** in the operator connection inventory. Use the granted MCP tools or the framework connection call interface in a normal-user task. Ask the owner to configure or grant the connection if unavailable. The framework owns startup, shutdown and credential injection. Keep tokens out of prompts, source, arguments, examples and logs. See [setup and schemas](references/setup.md).

1. Confirm the intended existing zone. For requested additions, confirm type, zone-relative owner, value and acceptance of provider-default TTL. Use `domain-get` with `Name` to confirm the zone. Inspect all existing records with `domain-record-list` using `Domain`, `Page` and `PerPage`. Start at page 1 and increment with a fixed positive page size until an empty page. The pinned handler discards provider pagination metadata. Stop on errors, truncated or unparseable output, or a repeated page. Check current tool schemas before calling and stop if the workflow inputs differ.
2. Compare owner, type and data across all pages. Compare DNS names case-insensitively, accounting for relative names, apex `@` and trailing dots. Validate IPv4 for A and IPv6 for AAAA and compare IPs by address value. Compare CNAME targets as DNS names and TXT by exact content, including case and whitespace. Clarify uncertain equivalence. Skip equivalent records and preserve distinct A, AAAA and TXT values. Block any new CNAME at the apex, alongside a different CNAME target, or alongside other record data. Block new A, AAAA or TXT at an owner with a CNAME. Apply these checks between pending additions too. Report conflicts without changing existing records.
3. Create only explicitly authorized additions using `domain-record-create` with `Domain`, `Type`, `Name` and `Data`. Use provider-accepted formatting, a fully qualified CNAME target and the requested TXT content. Decline custom-TTL requests before writing because this tool has no TTL input. Zone creation, updates and deletions are outside default scope. Submit one addition at a time and report partial success if a later record is blocked.
4. Read back each creation using `domain-record-get` if an ID is available or re-list the zone. After an ambiguous response or write timeout, re-list all pages before retrying. Report an equivalent record found during reconciliation. If absent, retry only if inspection succeeded, conflict checks still pass, and the authorization covers retrying. Stop when state remains uncertain. Concurrent writes and retries can produce duplicates. Report provider readback, answers from delegated authoritative servers, and public recursive resolver cache observations separately.

The networking service includes other tools. Framework grants and these instructions do not enforce a zone or type subset. The token's scopes control API operation permissions. Use only the approved zone and operations.
