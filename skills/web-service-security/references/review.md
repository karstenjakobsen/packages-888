# Web service and integration security review

This guide adapts and modifies portable Cloudflare guidance. See [upstream provenance](../UPSTREAM.md).

- Trace identities and trust boundaries across ingress, proxy, app, database and external services. Require authentication and authorization for protected operations and objects, scoped by role, tenant and ownership. Deny absent, invalid or expired credentials and fail closed when verification errors or dependencies fail. Verify signature, issuer, audience, expiry and replay controls where applicable. Test allowed, unauthenticated, wrong-role and wrong-tenant cases through normal entry points.
- Verify TLS hostname/certificate validation, trusted reverse proxy hops and sanitized forwarding headers. Trust forwarded scheme, host and client IP only via configured proxies. Keep upstream and admin bindings private as appropriate. Evaluate headers in the context of actual transport, browser behavior and access controls. Use Secure, HttpOnly and appropriate SameSite session cookies, minimal scope, session rotation and expiry. For cookie-authenticated state changes validate CSRF protection and trusted origins. Configure CORS narrowly and review preflight and credential behavior.
- Bound request and response bytes including decompressed size, timeouts, concurrency, queues and resource use at the applicable layers. Stream large bodies with backpressure and cancellation. Limit buffering to bounded inputs and test oversized, slow, aborted and concurrent requests. Choose limits from the deployed runtime and workload.
- Use a cryptographic generator for security tokens. For comparisons use the runtime's timing-safe API and equal-length buffers or fixed-size digests where appropriate. In Node use node:crypto randomBytes and timingSafeEqual. Review the surrounding code for timing leaks and use the framework's password or signature verifier where applicable. [Node.js crypto](https://nodejs.org/api/crypto.html#cryptotimingsafeequala-b)
- Keep ordinary configuration in tracked source and secrets in approved framework stores/runtime bindings. Scope credentials to service and purpose. Redact auth headers, cookies, query secrets, bodies and environment dumps from logs, traces and error messages. Use structured events with safe fields. Avoid requesting secret values in chat.
- Attach credentials only to the configured HTTPS origin. Disable automatic redirect following, resolve each Location with the actual client parser, validate each hop and stop on origin changes or downgrade. Review cookie jars, proxy configuration and credential middleware for implicit forwarding. See [credential target review](credential-target.md).
- For server-side fetches constrain destinations and network egress. Review resolution and actual connection addresses at every hop, including IPv4, IPv6 and mapped addresses, loopback, private, link-local and metadata ranges as applicable. Address DNS rebinding by tying validation to the actual connection, preserving TLS verification and using controlled egress where appropriate. Review redirects and proxy bypasses. URL-string checks alone cannot establish SSRF defenses. Prefer library calls to shell commands. If invoking a program, use a fixed executable and argument boundaries, constrain options and inputs, and avoid shell interpolation.
- Run untrusted execution separately from the credential-bearing control service. Use restricted identities, CPU/memory/time/process quotas, minimal volumes and egress, and isolate host sockets including the Docker socket. Explicit runtime bindings remain appropriate for trusted deployed services. Review actual OS, runtime and tool policy enforcement. Text instructions and data returned by tools grant no privilege or connection access.
- Establish baseline behavior, stage the smallest authorized change, and set rollback thresholds and restore steps. Test positive and negative paths including redirects, auth failures and error redaction. Verify service health and required integrations after rollout or rollback, and record gaps that need further evidence.
