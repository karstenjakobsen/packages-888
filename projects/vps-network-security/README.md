# VPS network security
Authorized 2026-11-18 for 212.132.68.43 by owner: permit application ingress only from 86.52.144.219 and 87.49.147.6.
The inet nftables gate runs at input/forward priority -10, before UFW, Fail2ban and Tailscale/Docker accepts. Existing UFW remains a second layer. It blocks unsolicited application ingress over IPv4, IPv6 and tailscale0 from all other sources, including pre-existing inbound connections; replies to outbound connections remain allowed. DHCPv4 and essential ICMP error/IPv6 neighbor control are explicitly preserved. Bridge-origin container egress forwarding remains unchanged. Source addresses are network controls, not application authentication.
Deploy only after nft syntax validation, effective listener review, tested administrator management access, recovery and scheduled rollback. Install ingress.nft at /etc/vps-network-security/ingress.nft (root0644), apply script at /usr/local/sbin/vps-apply-ingress (root0755) and unit at /etc/systemd/system/vps-ingress-guard.service. Enable/start the named service. Never flush unrelated rules. Rollback deletes only table inet vps_ingress_guard and restores backed-up UFW user rules if changed, then disables the service.
Strict restriction blocks incoming Tailscale peers, public web users, webhooks, public ACME HTTP-01/TLS-ALPN-01 and external monitors. Existing TLS certificate expires 2027-02-16; configure DNS-01 renewal through an owner-managed credential binding before renewal is needed.
Root/password SSH authentication requires separately tested key logins before disablement; no key material or credentials are tracked here.
